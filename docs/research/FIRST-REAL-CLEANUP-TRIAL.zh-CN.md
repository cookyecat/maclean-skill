# 首次真实清理试验（可复制 Prompt · v1）

> **目标**：让 AI 代替普通用户完成候选选择；用户只需要审核 **一份清楚的批量计划**，再按执行器要求在 Mac 终端确认。试验会删除真实文件，因此必须先有单独的实际授权。

请通过当前已授权的 Mac MCP Gateway 使用 MacLean，对我的 Mac 开展首次真实清理试验。遵守 GitHub research 分支的两张设计基线图。

**阶段 A — 身份确认和只读分析**

1. 读取当前实际加载的 `SKILL.md`、manifest 和原版脚本，校验真实版本和所有 hash。优先使用已验收的正式稳定版 v1.3.1。如果改用尚未正式发布的 v1.4.0 候选，必须先对准确候选 ZIP 通过独立完整 G0–G7 验收，未通过则不得清理。
2. 通过已授权 Gateway 仅执行原版 Home、Library、triage 审计。默认只做许可技术叶目录的测量；禁止扫描 Home/Library 根、个人通讯和文档、凭据及未批准的 Profile 区域。
3. 由 AI **主动筛选**高置信度、可重建、收益值得且不影响当前服务的缓存。默认自动排除 ACTIVE、PROTECTED、UNKNOWN，飞书/Chrome Profile 的 CacheStorage，离线数据疑点，以及当前/回退版本。不要把所有 REVIEW 自动当作推荐；不得停止正在运行的 Codex、Cursor、Gateway、npm 等服务。
4. 生成一份**未批准**的精确目标清单，分别显示：总预计分配空间、被排除的空间、每项种类/准确路径/大小/理由/重建代价/活动状态。详细路径仅在本机受控报告或专门的审批视图展示，不在公开日志中输出。不要假定 `du` 的大小就是 APFS 实际可回收空间。
5. 使用原版 `cleanup_plan.py --plan ...` 做 dry-run，`user_approved=false`，保证不执行 `--apply`。可用独立的隔离测试夹具测试安全否决。

**阶段 B — 等待用户决定**

把刚才的精确目标和 dry-run 结果集中向我展示一次，**到此停止，不得自主推进删除**。请明确问：“是否批准仅清理上述这些精确目标？” 如果我没有以新的消息明确批准这份计划，任何时候都不得把 `user_approved` 改成 `true`。

**阶段 C — 仅在我明确批准后的后续对话执行**

1. 确认授权指向同一份未变化的计划与准确路径；重新测量并运行活动进程、安全/隐私/符号链接/文件身份检查。数据或进程状态变化时，重新提交需要确认的方案，不偷偷扩充。
2. 根据原版 Skill 的协议生成已批准计划，但仍必须由 Mac 上真实物理交互终端完成 `DELETE` 确认；**禁止通过代理模拟终端、伪造输入、通过管道输入 DELETE、关闭保护或直接用 rm/shutil 删除**。
3. 只有原版执行器允许时才执行 `--apply`；如当前 Gateway 无法实现真正的人类终端交互，请给出唯一一条可供我自己在 Mac Terminal 执行的原版命令，不尝试绕过。
4. 执行后核对逐项结果、真实磁盘可用量前后差值、失败或安全阻断项；保留私有脱敏日志。不要宣称空间一定完全回收。

默认不要纳入个人 Profile CacheStorage、整个应用配置、数据库、项目源码、`.venv`、Homebrew/Conda 环境、Git worktrees 根目录或仍有进程引用的缓存。没有足够低风险候选时，请明确说本轮不建议删，不得为凑出“可回收 GiB”而放宽规则。
