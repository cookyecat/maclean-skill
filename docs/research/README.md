# MacLean · Research Architecture Baseline

> **产品理念（冻结）**：**用户不用懂技术，AI 能判断得准，程序能删得安全。**
>
> 详见 [PRODUCT-PHILOSOPHY-v1.md](PRODUCT-PHILOSOPHY-v1.md)。它是本研究分支的最高层产品约束：用户体验、AI 决策与执行器安全缺一不可。

本目录专门固定 MacLean 从“能扫描、能清理”到“AI 能正确决策、普通用户只需确认一次”的研究设计。

## 已冻结的两张框图

1. **[AI 清理决策三态图 · v1.0](AI-DECISION-STATES-v1.md)**：**推荐清理 / 暂缓清理 / 保留或证据不足**，并明确硬安全否决、批准、重检、终端确认的先后关系。
2. **[MacLean 智能清理目标交互图 · v1.0](ONE-CLICK-CLEANUP-UX-v1.md)**：保留原始示意中的 **3.8 GiB 推荐、5.2 GiB 自动保留、2.3 GiB 可重建缓存、1.5 GiB 旧更新包和日志**，显式标注它们都是示意数字。

## 版本与工程关系

- **分支**：`research/ai-decision-batch-ux-v1`，以 `feat/broad-cache-discovery-v1.4` 的 commit `fa7f55c5f1f724851949bc6e6ea96ed74a973df4` 为基线。
- 该 research 分支 **只维护设计合同**，**不自动合并** 至发布的 `main`，不改变已发布 v1.3.1。
- 目前在 `main` 上的 v1.3.1 为稳定公开版；v1.4.0 仍是未经完整新版 G0–G7 验收的开发候选。
- 图 2 为 **目标交互**，不是已实现可点击的清理 UI；本项目仍使用实际终端 DELETE 作为执行门槛。

## 防漂移规则

任何变更若影响 **AI 三态、默认推荐资格、硬安全否决、个人 Profile 缓存处理、单批授权、物理终端确认、真实回收反馈**：

1. 必须先在 research 分支提出 RFC（旧图不直接覆盖，保留历史版本）。
2. 说明场景和失败案例，并与本目录的两个基线逐条对照。
3. 为新的行为补充负向测试与人工验收。
4. 评审通过后才能把新的设计版本同步到实现/发布分支。
5. 不得将“更大清理量”或“更少点击”单独视为正确性提高。

## 当前先做什么

先用已经通过安全验收的发行版本开展 **真实、明确授权的低风险清理试验**；若使用 v1.4 候选执行删除，则必须先完成**针对准确安装包的完整 G0–G7**。第一批默认不选飞书/Chrome Profile 缓存，也不清理正在使用的 npm/npx、Codex/Cursor 组件。仅生成 AI 推荐的精确目标批次，审核后单次授权，执行器最后复核；记录实际空间释放与失败原因。
