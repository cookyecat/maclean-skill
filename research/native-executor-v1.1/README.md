# MacLean Native Executor v1.1 — separate exact-approval prototype

> **用户不用懂技术，AI 能判断得准，程序能删得安全。**

**Status:** Research branch. A runnable **standalone native executor prototype**, not a released or installed MacLean Skill. This version deliberately does NOT change the original v1.4.0 `cleanup_plan.py`, stable `main`, original workstations services or the previous unapproved plan.

## Product path

1. **Identify regenerable known caches** with original authenticated v1.4.0 Privacy Safe read-only triage. No global process-family veto for simple catalogued native cache maintenance.
2. **Generate one unapproved draft** with exact kind, path, candidate ID, native method, inode/device identity and rebuild warning. Only known `npm.cache.clean_all`, `uv.cache.prune` and `npm.cache.npx.rm_exact` methods are available in this research branch.
3. **Show human-readable DEFAULT / OPTIONAL items** without exposing actual private cache paths. Users can check or uncheck a batch; frontend integration remains future work.
4. **Preview selected exact IDs**, always reconciling target identity, original path/privacy allowlist, fresh triage, risk warnings and materially changed allocation. A draft expires after two hours.
5. **Execution requires an independent manually authored approval record** bound to SHA-256 of draft bytes + selected IDs, an interactive physical terminal confirmation repeating the digest prefix, and a final live reread. This is not automated by ChatGPT. Actual user approval has NOT been given in this session.
6. **Exact operation-based execution**, not unguarded recursive directory deletion: pinned native npm and uv methods; distinct per-application configs; locks/journal and APFS before/after delta.
7. **npx remains preview-only**: v1.0 proved native per-key `rm` can break a running tool's subsequent lazy file load even though npm reports success.

## What is executable, exactly?

| Method | Exact catalog location | v1.1 standalone method |
|---|---|---|
| `npm.cache.clean_all` | `~/.npm/_cacache` | Native `npm cache clean --force` with config pinned to this npm cache root; requires explicit approval + interactive confirmation. **In-flight npm concurrency remains not fully accepted** |
| `uv.cache.prune` | `~/.cache/uv` | Native `uv cache prune`, using a dedicated cache root and uv-native locking. Prune is not a promise of complete cache removal |
| `npm.cache.npx.rm_exact` | `~/.npm/_npx/<16-hex-key>` | **PREVIEW ONLY**, explicitly denied even if selected and approved |

The original verified v1.4 `cleanup_plan.resolve_target` remains the source of path/Privacy Safe validation. Exact pinned SHA-256 files are checked **before** running original script. Original app-family process guard is NOT silently weakened or spoofed; the separate native executor instead has its own operation contract. The original executor still behaves as released.

## Safety implementation

- Cannot run with sudo/root; original pinned bundle required.
- Target path must be a known exact catalog identity. Parent directory, Profile, Chrome, Feishu and arbitrary string inputs are rejected.
- Plans: owner-private 0600 file under 0700 directory; no overwrite.
- Time-bound plan, SHA digest, target inode/device and candidate identity consistency are rechecked before every operation. Material size changes trigger fresh review.
- Approval is a **separate** owner-private JSON document with exact `selected_ids` and draft SHA, NOT generated by this executor; every actual apply requires an interactive terminal `DELETE <digest-prefix>`.
- A file named `native-apply-<digest>.lock` and fsynced `.jsonl` per-target START/BEFORE_NATIVE/SUCCESS/COMPLETE receipts remain after execution, rejecting silent replay. An interrupted batch may be partly completed and requires review; transactions cannot roll back native commands.
- No shell invocation or user-supplied extra flags reach npm/uv; npm configurations are isolated and forced.
- npm clean is fundamentally more aggressive than npm verify. Concurrent npm installation may be impacted despite content being regenerable: the exact method must be acknowledged at batch consent. This branch is **not certified production-ready**.

## Reproduce safely (read-only only on a real Mac)

A pinned original v1.4.0 bundle must be provided; a nonmatching original file hash is denied. Only run preview and review in a real user HOME during research:

```sh
umask 077
p=$(mktemp -d /tmp/maclean-v11-review.XXXXXX)
chmod 700 "$p"
python3 research/native-executor-v1.1/native_executor.py \
  --skill-root "/path/to/verified/macos-disk-auditor" \
  --create-draft "$p/unapproved.json"
python3 research/native-executor-v1.1/native_executor.py \
  --skill-root "/path/to/verified/macos-disk-auditor" \
  --plan "$p/unapproved.json" --review
```

The real `--apply` code path is **not** part of the preceding commands and must NOT be called without an independently approved exact plan. To avoid accidental live effects, fixture-only unit tests mock original source and map the executor's native operations into owner-private TemporaryDirectory caches:

```sh
cd research/native-executor-v1.1
python3 -m unittest -v test_native_executor_v11
```

## Not proven

- Complete production concurrency safety for npm full clean while an unrelated npm operation is in flight.
- Atomic filesystem safety against malicious concurrent replacement of native tool cache roots; current preflight checks are not dirfd-based and the native programs still own their own path access.
- Exact in-use npx entry protection; npx is therefore preview-only.
- Real user APFS reclaimed bytes: no live user cache was deleted.
- Stable release integration/UI and a fully reviewed install package; the research branch does not alter original Skill release.

**Next:** independent concurrency trials of native npm clean with active npm installs, file descriptor and path provenance review, approved batch audit, UI integration, and explicit limited live pilot consent. Do NOT bypass the old executor by disabling its process guards.
